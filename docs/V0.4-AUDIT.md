## Ragdoll audit

Selectable operators do not require separate gameplay physics. All three current operators use identical joint positions, articulated topology, actor collision, hit detection and movement. Helmet/cloth treatment changes appearance. The same model hands off from life to death and shares uploaded geometry. Weapon finish now survives the model's weapon changes and death clone too.

The solver now resolves all six box faces, floors and ceilings, has softer cross-body constraints, weapon-dependent impulses and sleeping bodies. It runs at 60 Hz with six constraint iterations, retains at most five corpses for six seconds, and is disabled on Potato. Tests cover finite motion, floor contact, bounded stretch and shared geometry lifetime.

This remains a point-and-distance approximation. It can look rubbery; limbs lack anatomical angular limits and self-collision; fast bodies can tunnel through thin obstacles; weapons remain attached. Next improvement order: anatomical knee/elbow limits, swept contact, a short authored hit/death blend, then optional dropped weapons. Keep hitboxes unchanged, preserve enemy/team readability across every skin, and measure cost before raising body counts. Cosmetic variety is safe only while these invariants are enforced.

## Progression contract

- Start with 200 **practice** KM. Eligible completed rounds against active bots lasting at least 30 seconds earn 20–60 KM. Targets, empty warmup and benchmark runs do not earn rewards.
- Daily reset is 00:00 UTC; weekly reset is Monday 00:00 UTC. Challenges rotate from authored data shipped in advance, not generated at runtime.
- Unlocking grants ownership; equipping is separate and never changes gun statistics or movement. No loot boxes or randomized rewards.
- Server profiles start at zero; local balances are never imported. SQLite keeps transactional ownership/balance state and unique ledger events. Earned and paid columns are separate; paid grants throw an explicit disabled error. Payment receipt uniqueness is scaffolded, but no provider, checkout, verification, refunds or purchase endpoint exists.
- Production rewards must originate from completed authoritative rounds bound to authenticated accounts. That connection is not implemented. Local receipts are not safe evidence of play.

## Verification and second self-audit

54 gameplay/presentation tests and 9 backend/network tests passed, including two independent WebSocket connections. Lint, full TypeScript checking, server compilation and production build passed. The production build still reports a large client chunk warning.

Browser inspection confirmed the new Foundry lobby, operator render, weapon cards and locker. Selecting Warden and unlocking Frost reduced the practice wallet from 200 to 80; equipping Frost updated the visible gun illustrations. Later reload/benchmark checks were interrupted by the browser connection closing. Therefore persistence across a real reload, a current v0.4 FPS result, full result-screen visual QA and unrestricted pointer-lock play remain **unverified**. The old v0.3 benchmark is historical, not a v0.4 result.

The second audit fixed malformed-storage startup failure, inaccurate metal impact classification, missing cosmetic propagation to character weapons, network jump input latching, and server results incorrectly phrased from player zero’s perspective. It also verified identical operator rig topology.

Dependency audit reported 11 entries (8 high, 2 moderate, 1 low) in the starter/framework tree. The direct room-server dependency is patched ws 8.21.1; older nested ws and other framework dependencies still have advisories. Complete a compatibility-tested framework update before deploying. Do not mistake a passing build or authoritative server for full anti-cheat or production security.

## Next release gates

1. Finish browser play/listening sessions, record current Balanced/Potato performance and test EDGE reach with humans. Measure frame pacing, not just average FPS.
2. Connect the browser to the server: input sequence handling, prediction/reconciliation, remote interpolation, authoritative event rendering and reconnect screens. Test at 50/100/150 ms latency and with packet interruption.
3. Add authenticated accounts and settle completed server matches exactly once. Persist challenge claims/ownership server-side; retain local practice as a separate mode.
4. Improve anatomical ragdoll limits and weapon animation, then test silhouette readability and performance for every cosmetic. Grow content only after these gates.

## Continuation: private rooms connected

The browser integration now exists: create/join UI, connection states, local movement prediction with applied-input reconciliation, remote transform smoothing, sequenced authoritative events, and per-spawn primaries. Two browser instances joined one duel; the receiving HUDs showed their own players; one recorded a frag while the other displayed its matching death recap, then successfully deployed with TWIN. This supersedes the earlier table's “browser not connected” limitation. Online rewards/account integration remain absent. Full pointer lock was blocked in the embedded browser; tests used drag aim.

The follow-up audit fixed local-ID/team assumptions, required exact acknowledgement of partially applied input frames, prevented previous-life inputs from crossing deployment, bounded replay/event storage, avoided re-sending the entire event ring to each client, and separated room status from the drag-aim hint. Combat feedback is still server-confirmed and therefore latency-sensitive; remote smoothing is not full buffered interpolation. Read MULTIPLAYER.md for the current protocol and remaining work.
