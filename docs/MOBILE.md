# Mobile browser support
Landscape touch controls: left stick moves, right-side drag aims, FIRE can also be dragged while held. AIM holds ADS (knife stab for EDGE). Separate jump, crouch, slide, reload and weapon swap. The sliders button adjusts control size, edge spacing and touch sensitivity; preferences are saved locally to this device. Optional gyro requires a secure page and motion permission on supported browsers. Portrait displays a rotate prompt. Browser fullscreen remains optional because iPhone support varies.

Uses the same simulation, recoil, server input, reconnect handling and account flow as desktop. No auto-fire, aim magnetism or damage advantage. Touch input clears on release, cancellation, lost capture, blur, orientation changes, chat and leaving active play. No protocol change.

Mobile rendering starts below native resolution and adapts between 0.55 and 1 CSS-pixel ratio based on sustained frame time. Mobile disables dynamic shadows and bounds sparks, ragdolls and impact marks. Simulation/network rates are unchanged; no guaranteed FPS is implied.

Verified locally: touch input/deadzone and resolution regression tests, desktop tests, lint, TypeScript, production build, touch-enabled Chromium phone/tablet viewports and practice entry. Chrome emulation is not an actual phone benchmark. Before announcing mobile release, play on real low-end Android and iPhone Safari: simultaneous move/aim/fire, gyro direction in both landscape orientations, permission denial, app switching/reconnect, notch/browser-bar resizing and sustained frame time. Test real mobile multiplayer on the deployed server. Aim assistance and separate touch queues remain deferred pending actual balance tests and player population.
