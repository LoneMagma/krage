# krage v0.3 follow-up — 7 September 2026

## Delivered in this pass

- AK first shot follows aim exactly; sustained fire increases spread. Recovering recoil retains mouse adjustments. Reload phases have feed/close sounds and the rifle has a sharper firing transient.
- Shared character support-hand targets now line up with the carried rifle; body hit flinch does not move player aim. The front sight has a physical supporting mount.
- Casual encounters start closer to the map interior. Bots patrol inner routes and require a view of silent opponents before acquiring them; fired opponents can draw a response. Default FFA is three Casual bots.
- Failed mouse capture offers a working drag-aim mode. Keyboard I/J/K/L turns the camera in that mode. Escape pauses during spawn selection; 1/2/3 select a primary and Enter deploys.
- Responsive lobby columns no longer overlap in the embedded viewport. Match layout is fixed to the viewport, clears the lobby's retained scroll position, and prevents the shared main element scrolling the HUD off-screen.
- Ragdolls clone live transforms while sharing geometry/materials. Disposing a corpse leaves the live character's GPU assets intact. Pose and ragdoll loops reuse temporary objects or scalar calculations rather than allocating vectors per joint.
- Settings includes a 30-second combat benchmark and retains the last report locally. It replaces the match with Foundry, five Regular bots and automatic movement/aim. Finishing or leaving restores ordinary controls; starting a normal match restores the 20-frag rule.

An earlier completed run recorded 56.95 FPS, 32.7 ms p95, 37 slow frames, 14 frags and five peak corpses. These runs used the same scenario setup but produced different fights; they are not a controlled before/after experiment. A fixed seed does not guarantee identical benchmark playback because automated aim is sampled per render frame. The final result is encouraging, not evidence of locked 60 FPS or physical low-end-device performance. Later changes add a small sight mount and correct HUD scroll; the table records the measured revision immediately before those visual fixes.

## Browser checks

Confirmed through actual UI interaction: match start, blocked-capture fallback, Shift crouch and stand, firing/ammo consumption, timed reload, incoming bot damage, death, primary choice and deployment with the double barrel. Escape was verified during spawn selection; pressing 3 selected TWIN, and Enter deployed with 100 health and 2/2 ammunition. Benchmark completes, shows measured results, preserves its last report and can return to a normal match. Lobby layout and weapon rendering were visually inspected. The HUD scroll correction was checked with both a screenshot and element positions at top = 0, scrollTop = 0.

Automated regression coverage remains separate from human playability: 44 checks pass, including camera/hitscan alignment, movement braking/collisions, jump and slide constraints, all modes/maps, bot combat, individual pellets, cover, recoil, loadouts and spawn rules. Lint, full TypeScript checking and production build also pass. The build reports a large client chunk warning; initial download/parsing remains a future optimization target.

## Boundaries

The embedded browser blocks pointer lock. Drag aiming is exercised; unrestricted captured mouse look and subjective sustained combat feel still need a full browser playtest. This is a local bot build, with procedural models, animations and sound. Authored character/arm animation, professional audio, map balance, physical low-end testing, long memory soaks and online multiplayer remain unfinished. Bullets are instantaneous collision rays with cosmetic trajectories, not ballistic projectiles. The supplied short video does not contain enough gameplay to establish feel.
