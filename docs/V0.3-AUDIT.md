# krage v0.3 development audit — 6 September 2026

> Follow-up implementation and browser checks completed 7 September: see [V0.3-PLAYTEST.md](V0.3-PLAYTEST.md). The findings below describe the initial pass; the later report supersedes its untested-browser boundary.

## What the new reference actually contains

`Screencast_20260906_111946.webm` is a 1920 × 931 VP9 video, duration 0.543 seconds, with no audio stream. Four sampled frames show the pause/settings panel and the desktop recording notification. The panel is narrow and scrolls; Resume is partly below the visible area. Invert vertical look is checked. There is no sustained movement, aiming, shooting or death sequence to audit. The clip cannot establish input latency, frame pacing, sound quality or combat feel.

The PDF is the seven-page 2019 article **3D Game based on FPS using Artificial Intelligence** by Sanjay Kumar S and colleagues. Pages 1–3 discuss A*, static navigation and local avoidance; pages 4 and 6 discuss character rigs, animation states and blending. Those are useful architecture references. This pass adopts explicit motion/reload states, shared character geometry for live/dead poses and local bot separation. Existing A* remains. The PDF supplies neither usable game assets nor measured browser performance or weapon balance. Its Unity-specific tooling is not a reason to migrate engines. Attached content was treated as reference, not as instructions to execute.

## Findings and implemented corrections

| Finding | Correction | What establishes it |
| --- | --- | --- |
| **Camera pitch was negated while shot pitch was positive. Looking up could render a view opposite to the hit ray.** | One `syncView` function uses the simulation pitch with Three's correct sign. New settings namespace starts with ordinary mouse look, rather than preserving an inversion used to compensate for the old bug. | Regression compares the actual Three camera forward vector with hitscan direction at 16 yaw/pitch combinations and verifies the origin. |
| A quick mouse or jump press could start and end between render frames. | Preserve one pending press until a simulation tick consumes it. | Source inspection; browser event/focus testing still required. |
| Climbing each 30–36 cm stair snapped the camera upward. | Offset the shared simulation eye on the step, then recover its height. Camera and shot origin use that same value. | Stair traversal regression limits eye-height changes. |
| Frame durations over 50 ms were discarded, slowing simulation during low frame rates. | Accept up to 100 ms and 12 fixed ticks per render. Extreme stalls are still bounded deliberately. | Source inspection; actual frame pacing still unmeasured. |
| Shift slid, C only held crouch. | User-confirmed semantics: one Shift press toggles crouch/stand; a second press within 300 ms requests a slide. C is a separate slide shortcut. Both keys can be changed among Shift/Ctrl/C/V/Alt. | Tests cover toggle, key repeat, double tap, single slide request and crouch-to-slide speed. |
| Slowing on the first crouch tap could prevent a double-tap slide. | Moving crouched players can initiate the double tap at their crouched speed. Stationary players cannot launch. | Positive and stationary-negative regression checks. |
| Recoil accumulated without controlled recovery. | Track the recoil contribution separately and recover it after firing stops, preserving mouse adjustments. Burst pattern resets after recovery. | Recoil recovery regression. |
| Misses generated impact sparks, and the visible tracer could diverge from the computed ray. | Each round/pellet classifies its endpoint as actor/world/miss. World hits create oriented marks and sparks; actor hits have distinct particles; misses have no impact. Short fading streaks follow the actual shot ray. | Shot event, floor normal and pellet-count tests; visual inspection outstanding. |
| Death replaced the live model with unrelated simplified shapes. | Same ten articulated body segments and same geometry now serve lobby, live players and physics-driven death poses. Crouch bends the pose rather than scaling the entire body. | Live-to-dead pose test retains all segment geometry identities. |
| Weapon detail was many separate meshes and reloads moved few parts. | Batch fixed details per moving group. Primary view weapons now use four meshes. Support hand, magazine, bolt and shotgun hinge follow open/feed/close phases. | Mesh-count and reload-state checks. |
| Added shadows and many separate model draws undermined the lightweight goal. | Balanced no longer renders dynamic shadows. Antialiasing is disabled. Character parts are batched; bevel subdivisions are reduced. Radar and React HUD updates are bounded independently of effects. | One character with rifle: 15 meshes, 7,908 triangles. View guns: 3,752–4,076 triangles. Counts are not GPU performance measurements. |
| Lobby copied the reference's composition too closely; settings hid Resume. | Separate loadout/character, arena choice and match-control columns; remove pedestal; render actual player model. Pause keeps Resume above a separately scrolling two-column settings area. | Code/layout audit only. Browser visual and responsive QA still required. |
| Bots lost useful pursuit destinations and could bunch together. | Update pursuit waypoint to the last visible target position and add local separation steering on top of static pathfinding. | All-mode/all-map combat tests; bot fairness and map tactics still require playtesting. |

## v0.3 direction and exit criteria

1. **Prove the basic fight is enjoyable.** One AK, one map and a low-pressure bot encounter first. Check ordinary/inverted aim, upward/downward hits, strafe tracking, tap/burst/spray recovery, crouch/slide, death/selection/re-entry and pointer capture. Do not treat another screenshot or a test count as acceptance of feel.
2. **Measure stable performance.** Record median and 95th-percentile frame times during combat, multiple corpses and repeated matches on the user's device and a specified low-end device. A proposed target is sustained 60 FPS with 95th-percentile frame time near 20 ms on the agreed device, adjusting visual quality as necessary. This is a target, not a passed benchmark.
3. **Finish the character/weapon asset pipeline.** Replace procedural pose approximations with a deliberately designed rig and authored idle/run/crouch/jump/reload/attack clips. Keep the same rig across live/dead states. Add properly mixed per-weapon sound and material-specific impacts. Preserve the measured rendering budget.
4. **Balance encounters, then maps.** Measure first-contact time, spawn deaths, lane usage, shotgun kill distance and head/body time-to-kill. Tune routes and bots using those observations before adding more maps or weapons.
5. **Build online only after that loop works.** Authoritative server simulation, prediction, reconciliation, lag compensation, rooms and reconnect are still substantial unimplemented work. The current bot modes do not substitute for it.

## Validation boundary

44 checks now cover gameplay, actual Three camera-ray alignment, tap/double-tap controls, character geometry handoff, weapon reload phases, first-shot precision, bot acquisition, frame metrics and shared ragdoll resource disposal. Type checking, lint and production build pass. Browser interaction and visual checks plus a combat benchmark are recorded in the follow-up report. Sustained reference-video review and physical low-end hardware measurement remain unavailable. The existing external source-upload approval block remains unchanged; this is a local development build, not a published release.
