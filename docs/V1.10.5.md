# KRAGE 1.10.5

## Changes
- Replaced legacy coarse-pointer layout overrides with width/height based phone, tablet and short-screen layouts in `app/responsive.css`. Desktop styling remains intact.
- Portrait menus work without a blocking rotation wall. Active portrait play offers a nonblocking landscape prompt; browser fullscreen/orientation requests remain best-effort.
- Settings, locker, challenges and room panels have bounded internal scrolling. Controls remain reachable; no global horizontal scrolling. Visible settings tabs are preserved. Small landscape create-room screens omit the pre-creation invitation placeholders; live party previews remain.
- HUD reserves its upper corners for health/ammo and lower corners for touch input. Compact match announcements, kill feed and chat notifications avoid the reticle. Respawn actions and results remain reachable.
- Touch layouts use viewport-safe pixel bounds and collision repair. Movement/fire support simultaneous pointers and clear held input on resize/cancel/blur. Version 3 layout storage intentionally starts with new defaults; old version 2 storage is retained but not loaded. New edits persist locally. Left-hand/reset options remain available.
- Chat follows the visible viewport when the software keyboard opens. Safe-area insets are respected.
- Vera uses an upright carry; Sable a lowered diagonal carry; Flint rests long weapons muzzle-down and carries shorter weapons. Hands follow grips/rest points, with body weight/shoulder changes. Weapon scale stays fixed. Rook and Blake retain their carry definitions. Portrait cameras allow clearance for upright weapons.
- Version metadata updated to 1.10.5. Room protocol is now 25; no database migration.

## Validation
Gameplay/presentation/results: 140 tests; room server: 38; accounts: 5. Lint, TypeScript and Render production build passed. 67 browser layout checks and 12 respawn/results/chat/keyboard-viewport checks passed without browser errors. Browser evidence is recorded locally in `outputs/1105-browser.json` and screenshots; match-state checks in `outputs/1105-states.json`. Emulated phone/tablet coverage is not a real-device performance certification.

## Deployment
Build from this source archive with `npm ci` then `npm run build:render`; start using `npm run start:render`. Room service: `npm run build:server`, then `node server/index.mjs`. Configure the existing production account/room environment separately; secrets, saved accounts, dependencies and old archives are excluded. See DEPLOY.md and DOMAIN-KRAGE-PACIFY.md.

Before public promotion, run real Android and iPhone playtests: browser bars, keyboard, both landscape orientations, multitouch, fullscreen refusal, account sync, reconnection and a multi-player match. This build has not been deployed by the coding session.
